# End-to-end results: spindoctor-qwerty-copilot 1.1.0

Run on 2026-10-10 (PT) in a clean-room copy (empty folder, empty HOME, `env -i` with PATH=/usr/bin:/bin, no access to engine
development folders), following only this README: `copilot plugin marketplace add ./spindoctor-qwerty-copilot` and
`copilot plugin install spindoctor-qwerty@spindoctor-qwerty-copilot`, driven by `tests/copilot_host_check.py`.

**Mode:** real host, scripted model. **GitHub Copilot CLI 1.0.95** was installed from npm (`npm i @github/copilot@1.0.95`) on a
Linux test machine and used with no GitHub account, no sign-in and no API key. Plugin management (marketplace add, install, list,
`mcp get`, `skill list`, disable, enable, uninstall, marketplace remove) needs no authentication. Sessions used Copilot CLI's
documented BYOK mode (`COPILOT_PROVIDER_BASE_URL` + `COPILOT_MODEL`; "GitHub authentication is not required when using a custom
provider") pointed at `tests/stub_llm.py`, a local scripted OpenAI-compatible endpoint that returns pre-written tool calls. It is not
an LLM. Copilot CLI offered the model the six plugin tools (`spindoctor-qwerty-spindoctor_*`) plus its `skill` tool, executed the
scripted calls through the plugin's own MCP server (started from `mcp.json` with `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` expanded) and
fed the results back; `--agent spindoctor-qwerty:spindoctor-qwerty-helper` loaded the custom agent's prompt and tool set.

**Format check:** the Copilot CLI plugin reference (docs.github.com/en/copilot/reference/cli-plugin-reference, read 2026-10-10)
recognizes Agent Plugins 1.0.0 and 1.1.0 `$schema` values, reads `plugin.json`, `skills/` and `mcp.json` at the root and
Copilot-specific agents/commands under `com.github.copilot/`, and looks for a marketplace in `.github/plugin/marketplace.json`.
`plugin.json` and `mcp.json` also validate against the official Agent Plugins 1.1.0 JSON schemas.

**Parity target:** the updated SpinDoctor 3.1.2. Publishing was approved by Russell on the basis of the updated 3.1.2 passing its
own suite 18/18, with the three 29-qubit test checks adapted to the 298-qubit limit.

## Notes

- **Preset differences (5 of qc-001..qc-025):** CPU-only reference instead of OpenCL GPU fields, tranche checkpoint text, state
  file name. They're documented in `tests/e2e_mcp.py` and are the same in every spindoctor-qwerty repo.
- **D-Bus:** on headless Linux each Copilot CLI run started a D-Bus session daemon that stayed behind (hundreds piled up during
  development and exhausted inotify instances). The check sets `DBUS_SESSION_BUS_ADDRESS=disabled:` for every run; none are left.
- **Slash commands in `-p` mode:** a prompt like `/qwerty-preset qc-001` is passed to the model as text in non-interactive mode;
  Copilot CLI lists the commands as skills, which the model loads with its `skill` tool. Interactive `/` completion wasn't tested.
- **Not tested:** VS Code and other Copilot surfaces, interactive sessions, real models, installs from GitHub (tested from a clone;
  the post-push check installs from a fresh clone of this repo).
